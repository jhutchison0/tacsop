## EPISODE 1 — LLM coordinate-generation detour (guardrails → sextants → thrown out for coordinate-free)

- **Session docs:** `20251225_guardrails_pipeline.md`, `20251225_map_repair_and_model_analysis.md`, `20251226_batch_generation_and_coord_parsing.md`, `20251226_sextant_map_generation.md`, `20251226_sextant_batch_pipeline_fixes.md` → superseded by `20260110_coordinate_free_narrative_generation.md`. **~5 sessions building coordinate-policing machinery; the fix should have taken ~1–2.** (~3 sessions avoidable; sextant geometry + A* coherence were genuinely reused, so not all 5 were waste.)
- **What happened:** The fine-tuned Qwen2.5-7B entered "degenerate coordinate loops after ~200 valid tiles" on large maps. Three successive architectures were built to *police* the model's coordinate output — real-time StoppingCriteria guardrails, a 3-stage skeleton/tiles/zones pipeline, then 6-way "sextant" chunking — each partially failing (`sextant_map_generation.md`: "Sextants 1, 3, 5 consistently fail with monotonic sequences"). The Jan 10 redesign reversed the premise: "the LLM generates terrain *sequences* … while Python handles coordinate *assignment* (deterministic, always valid) … OOB becomes **impossible by design**."
- **Classification: PREVENTABLE-BY-PLANNING.** The winning insight is a stated general principle, not a surprise — `coordinate_free_narrative_generation.md`: "The LLM's strength is *terrain semantics* … Its weakness is *spatial bookkeeping*." A single up-front "what should the LLM own vs. deterministic Python?" step reaches this before ~5 sessions of scaffolding to force coordinate generation to work. The plan's own root-cause list admits the scaffolding treated symptoms: "Guardrails stop, don't fix."
- **Element that would have helped most:** **Approaches-Considered** (compare "LLM places tiles" vs "LLM emits semantics, Python places" at design time).
- **Process gap a format can't fix:** `v0.6.5_map_tooling.md` was **Created 2025-12-26 — after** the guardrails (12-25) and first sextant work were already built. The plan documented the architecture rather than driving it. A format standard can't force a plan to be written *first*.

## EPISODE 2 — "Fine-tune a 7B model for map-gen" premise never validated, quietly displaced by the base model

- **Session docs:** `20251227_post_training_cleanup.md` → `20260110_v066_coherence_terrain.md` → `20260110_coordinate_free_narrative_generation.md` → `20260124_batch_training_pipeline.md` → `20260125_training_variety_cleanup.md`; verdict landed in `20260523_map_gen_v2_survey_and_conop.md` / `conop_001_map_generation_v2.md`. **The retrain deliverable was deferred across ≥3 sessions and never run to a decision; ~14h/iteration + 1.2 GB of weights sunk before formal retirement.**
- **What happened:** The stated goal of the whole v0.6.5 effort was "Generate 100-200 quality maps as training data for next fine-tuning iteration." That loop never closed — "retrain" is perpetually a next-step, and by late January production silently ran on the **base** `qwen2.5:7b` while "Evaluate fine-tuned model vs base Ollama for production use" sat unresolved (`training_variety_cleanup.md`). The v2 survey finally rendered the verdict: "the next 1.0× improvement requires architectural change, not more iterations within v1's envelope."
- **Classification: PREVENTABLE-BY-PLANNING.** Nothing about "does fine-tuning beat base?" needed months to learn — it needed the comparison run and a bar written down. `v0.6.5`'s Success Criteria measure completion rates and variety but contain **no criterion of the form "fine-tuned beats base by X"** and no kill-criterion. The team had the data to make the call in January (they were already running base) but no plan slot forcing the decision.
- **Element that would have helped most:** **Exit-criteria / kill-criteria** (a baseline comparison with a defined bar that kills the fine-tune bet if unmet).
- **Process gap a format can't fix:** The comparison existed as an implicit next-step with **no owner**; it was deferred indefinitely. A format can demand an exit criterion but can't assign someone to execute it or force the go/no-go.

## EPISODE 3 — Forest-biome variety prompt-chasing

- **Session docs:** `20260124_batch_training_pipeline.md` → `20260125_training_variety_cleanup.md` → `20260208_agent_team_forest_variety.md`. **~3 sessions circling one lever; ~2 avoidable.**
- **What happened:** Session 1 already diagnosed the root cause and named the real fixes: "The qwen2.5:7b model tends to generate mostly 'dense_vegetation' … This is a **model behavior issue, not pipeline issue**" with escape hatches ("Use different model for forest biome"). Two later sessions kept pulling the *prompt* lever anyway; `agent_team_forest_variety.md` hits the same wall: "dense_vegetation still dominant … strong bias … even with explicit percentage targets."
- **Classification: MIXED (leaning preventable).** Learning the 7B won't hit the target on the first try is legitimate discovery; re-running prompt-engineering twice more after the cause was already identified as intrinsic-model-bias is the avoidable part.
- **Element that would have helped most:** **Non-goals + Exit-criteria** (a one-line "we will not keep prompt-tuning a known-biased 7B past one iteration; escalate to a model swap or post-hoc rebalance").
- **Process gap a format can't fix:** The escape hatch was *written down* in session 1 but never *adopted as a stopping rule*. A format can prompt for exit criteria but can't make the team honor its own earlier off-ramp.

## EPISODE 4 — MAUT v2 acceptance metric never calibration-validated before it gated all four waves

- **Session docs:** rubric built in Wave 1 (`20260523_lodestar_w1_kickoff.md`, W1.4) and used to declare Wave 1 PASS (+29.2%) and to set the W3.9 bar; invalidity surfaced only at `20260527_w3_6_diagnostic_and_option_z_close.md` / `20260527_w3_7_findings.md`. **The metric silently gated ~4–5 sessions of Wave 1–3 work; a 1-afternoon check at Wave 1 would have surfaced the defect immediately.**
- **What happened:** At Wave 3, the cheapest GNN-refiner probe revealed that pure BiomeRule random palette-sampling *outscores* the real coherence chain (0.686 vs 0.620) on 4 of 6 criteria, and that the hand-built tutorial map `training_ground` scores **0.495 — below random**. "MAUT v2 measures terrain spread, not spatial structure." The entire v2 edifice ("beats v1 on MAUT," Wave 1 acceptance, the 0.6695 bar) rested on a metric whose construct validity was never checked against the known-good hand-built maps until Wave 3.
- **Classification: MIXED (leaning PREVENTABLE).** The exact failure locus (difference lives in minority-terrain placement below per-class statistical thresholds) was genuine discovery. But scoring the 4 archive maps + shuffled controls under MAUT — the check that exposes `training_ground`=0.495 — was a 1-afternoon step available from Wave 1. The CONOP treated MAUT only as a weight-tuning problem (§9: "tune MAUT criterion weights empirically per biome in W1.7") and its risk register (§8) assumed the metric valid — no risk entry for "MAUT doesn't measure what we want."
- **Element that would have helped most:** **Exit-criteria-checkpoints applied to the measuring instrument** — a construct-validity/calibration gate ("before this metric gates any wave, verify it rank-orders known-good > known-bad reference maps").
- **Process gap a format can't fix:** The plan *had* a MAUT line item; it was framed as weights, and nobody re-read it as a validity risk. A format can prompt "how will you validate the metric" but can't force the team to actually run the calibration.

## EPISODE 5 — BSPL ablation run on a baseline already known to be architecturally mode-collapsed

- **Session docs:** `20260524_w3_3_5_baseline_grade.md` (collapse found + explicit recommendation against ablating) → W3.3.6 entropy probe (same doc, "collapse is architecture-fundamental, not XE-specific") → `20260524_w3_4_bspl_adapter.md` → `20260524_w3_5_ablation_negative_result.md` (full 5-variant matrix, incl. an interrupted-then-resumed run). **~2 sessions on the full ablation; ~1 avoidable.**
- **What happened:** W3.3.5 found variety=0.000 at full generation and the python-prototyper stated: "**Do NOT launch W3.5 ablation on the current XE-only checkpoint** … will not produce interpretable results. The baseline must either be fixed or explicitly documented as the 'variety-collapse baseline' before ablation begins." W3.3.6 confirmed the collapse is architectural (all hexes share the biome embedding; the model has *no positional features*). The team ran the full 5-variant × 2-mask ablation anyway; every variant rendered identically ("`rough` × 469, Simpson D = 0.000") — exactly what the baseline diagnostics predicted.
- **Classification: MIXED.** The BSPL negative was the funded deliverable and has documentation value regardless (CONOP §3.1: "we run all 5 variants … Negative result for BSPL is a documented contribution"). But running the *full expensive matrix* on a baseline two diagnostics had already flagged as degenerate — against the implementer's explicit recommendation — is partly avoidable; a cheaper single-variant confirmation would have sufficed.
- **Element that would have helped most:** **Branches / pre-decided contingencies + an intra-wave checkpoint** — a gate between W3.3 (baseline) and W3.5 (ablation): "if the XE baseline produces zero variety and the cause is architectural, downgrade the ablation to a one-variant confirmation or fix the architecture first." The CONOP had wave-boundary gates but no checkpoint guarding the expensive ablation on baseline health (W3.5's condition was merely "Given W3.3 baseline + W3.4 adapter").
- **Process gap a format can't fix:** A **live diagnostic recommendation was overridden by the pre-committed plan.** The plan's momentum beat a fresh, correct signal. A format can add checkpoints, but the deeper failure — the plan out-ranking a mid-execution finding — is a plan-authority / re-read discipline issue a template can't legislate.

## EPISODE 6 — The GNN + BSPL research probe itself (Wave 3 as a whole)

- **Session docs:** the full W3 arc (`20260524_lodestar_w3_kickoff.md` through `20260528_post_w3_reset_and_adr_0003.md`). **~5–7 sessions; CONOP estimated Wave 3 at 5–6. It came in on budget.**
- **What happened:** A knowledge-graph → GNN → spectral-loss (BSPL) research direction, explicitly funded by the user as a research bet, returned a definitive negative and shipped Wave 1's rule-based chain as production per the "ships at every wave" intent.
- **Classification: DISCOVERY-PRICED-IN.** This is the honest-negative anchor. The failure mechanisms (XE modal-terrain basin; BSPL gradient death on saturated softmax; missing positional features) are non-obvious from architectural review; the CONOP pre-declared "a documented negative result is acceptable" and the wave landed near its own estimate. No realistic plan would have known the outcome without running it.
- **Element that would have helped most:** **NONE** — correctly priced in.
- **Note:** Wave 3.6 *invented* the discipline the earlier episodes lacked — "code-reviewer's cheap-test gate" (a 1-afternoon empirical falsifier before any multi-session investment), self-credited with saving ~6 sessions. The lesson for format design is to move that gate to the *front* of the plan rather than discovering it reactively mid-wave.

## SUMMARY

- **Total episodes:** 6 real churn episodes + 1 examined-and-cleared (WeGo).
- **Classification counts:** PREVENTABLE-BY-PLANNING = 2 (Ep1, Ep2); MIXED = 3 (Ep3, Ep4, Ep5); DISCOVERY-PRICED-IN = 1 (Ep6).
- **Concentration:** All churn is in map-generation; gameplay systems (rendering, hex grid, turn economy, WeGo) progressed cleanly. This is a domain where an unvalidated modeling assumption can silently gate many sessions — exactly the domain a good plan protects.

**Single strongest lesson for CONOP/OPORD format design:** Every preventable/mixed episode traces to one shape of failure — a **load-bearing assumption with no falsifier and no kill-criterion**: "the LLM can be made to place coordinates" (Ep1), "fine-tuning beats base" (Ep2), "prompt-tuning can fix model bias" (Ep3), "MAUT measures map quality" (Ep4), "the baseline is strong enough to ablate against" (Ep5). The CONOP/OPORD format should require, per objective, an **Assumptions block where each load-bearing assumption names its cheapest empirical falsifier and an exit/kill-criterion**, and — critically — extend this to the plan's own **acceptance metric**: any measuring instrument used as a gate must pass a construct-validity/calibration check (rank-orders known-good > known-bad references) *before* it is allowed to gate a wave. The repo proved the ROI itself: the reactive "cheap-test gate" invented in W3.6 was credited with saving ~6 sessions; institutionalizing it as a front-loaded format element is the highest-leverage change. A secondary element: **intra-wave checkpoints**, not just wave-boundary gates, so a live diagnostic ("do NOT run this on this baseline") has a defined slot to halt a pre-committed expensive step (Ep5).

**Live documents vs. shelf-ware (one sentence):** The repo's plan artifacts evolved from write-once shelf-ware in the v0.6.x era (`v0.6.5_map_tooling.md` was created mid-stream, had Phase 2 silently redesigned in place, left Phases 3–5 never ticked, and still reads "In Progress" months after being superseded) to genuinely live documents in the CONOP-001 era (a dated Status Log, a header flipped through DRAFT → each wave → CLOSING NEGATIVE → CLOSED, and falsified sub-proposals annotated and preserved as record) — so the incoming doctrine format standard is landing on a repo that had already, on its own, learned to keep its top-level plan live, and the remaining gap is up-front assumption/metric validation, not plan upkeep.
