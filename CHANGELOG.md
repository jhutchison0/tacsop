## [Unreleased]

### Changed
- **Environment engine moved to uv (drop-in level).** `uv venv --managed-python` + `uv pip` replace `python3 -m venv` + pip across all living docs (`CLAUDE.md`, `README.md`, `CONTEXT.md`); the `python-venv-management` skill is rebuilt as **3.0.0** on uv (pyenv → `uv python`, pip-tools → `uv pip compile`/`uv pip sync`, pipx → `uvx`, new uv failure modes, incumbent-migration order); the shift-left `CI.md` sidecar moves to `astral-sh/setup-uv` with built-in caching; in-code install hints say `uv pip install` (changed test-first; suite 268 → 269); `config/project.yaml` records `package_manager: "uv"` and drops the stale manual-numpy known issue. The 2026-08-03 doctrine entry was field-verified before propagation: a `pyvenv.cfg` sweep found 10 venvs where the name-glob saw 5, 8 rebuilt at exact parity (6,898 passing tests), pyenv retired from the machine, and the entry corrected from findings (`uv venv --clear`, freeze insurance, three dependency-drift classes). Propagated to 15 downstream repos. uv-native (`uv sync` + committed lockfile) deferred to a future cycle with its own ADR.
- **License switched from GPL v3 to Apache-2.0.** The repo was private with no distribution, so no GPL obligations were ever triggered; relicensing by the sole author is clean. Apache-2.0 fits a template repo whose content is copied into downstream projects: no copyleft friction on derivatives, attribution and license retention required (§4), explicit patent grant. `LICENSE` now carries the full canonical text (the prior file was a 22-line GPL stub), `README.md` and `pyproject.toml` (`license = "Apache-2.0"`, PEP 639; setuptools floor raised to >=77) updated to match.
- **Repository renamed `utils` → `tacsop`** (Tactical Standing Operating Procedure) per [ADR-0002](docs/adr/0002-rename-repository-to-tacsop.md). Living docs, `scripts/propagate_doctrine.py` (`UTILS_ROOT` → `TACSOP_ROOT`), and `scripts/adopt_doctrine.py` (`DEFAULT_UPSTREAM` now `~/projects/github/tacsop/`) updated. The `myproject` package placeholder and all historical docs are unchanged; old GitHub URLs redirect.

### Fixed
- **Running-prose em dashes in four template-copied docs** (`docs/plans/CONOP-FORMAT.md`, `docs/plans/OPORD-FORMAT.md`, `docs/session-doc-format.md`, `.claude/README.md`): 27 in-sentence dashes replaced per prose rule 8. Found by stx-server's bootstrap audit (CONCERN-4), which could not fix hub copies locally without forking doctrine. Headings, table cells, and list-label separators are exempt and untouched.
- `.claude/README.md` skills tree listed six of nine Level 0 skills; `SKILLS_FRAMEWORK.md`'s tree omitted `traversing-the-knowledge-base` and its per-skill inventory sections omitted `using-topic-branches`, `writing-simple-and-direct`, and `traversing-the-knowledge-base`. Both trees and the inventory now match the directory.
- `SKILLS_FRAMEWORK.md` description rule said one sentence while two shipped skills carry three; the rule now says one to three (stx-server gate review C8).
- **Windows portability**: `scripts/adopt_doctrine.py` now forces UTF-8 stdio at module load so the Unicode arrows (`→`) in status messages don't crash on Windows cp1252. Caught when `heimdall-darkroom` adopted the 2026-05-19 doctrine bundle as the first Windows downstream.
- **Windows portability**: `.claude/hooks/post-tool-shift-left-audit.sh` now normalizes Windows backslash paths to forward slashes before the case-glob match. Without this, the hook silently no-op'd on Windows because `*/src/<pkg>/*.py` could not match `C:\…\src\<pkg>\foo.py`. Recursive subdirectory matching also clarified in comments (case patterns match across slashes).
- **Windows portability**: `src/myproject/utils/logger.py` now catches `ZoneInfoNotFoundError` (a `KeyError` subclass, NOT `ImportError`/`ValueError`) in the timezone-resolution fallback. On Windows + Python 3.9+ without the `tzdata` package, `ZoneInfo("America/Chicago")` raises this exception; the prior except clause did not catch it and any caller of `get_logger()` would crash at import time. Originally surfaced in `heimdall-darkroom` on 2026-04-22, finally propagated.
- **Windows portability**: `tests/unit/test_adopt_doctrine.py::TestPlanCopies::test_sources_rooted_at_upstream` now uses `Path.is_relative_to` instead of `str(src).startswith("/fake/upstream/")` so the assertion works on Windows where `Path()` normalizes to backslash separators.
- **Windows portability**: `tests/unit/test_adopt_doctrine.py::TestSubstituteHook::test_executable_bit_preserved` now skips on `win32`. NTFS has no POSIX `+x` bit; `chmod(0o755)` is a no-op on Windows. Hooks invoked via `bash <path>` from the harness don't need the bit anyway.

### Added
- **Home-storage doctrine: `lake-conventions` 1.1.0** adds a `HOME-STORAGE.md` sidecar for personal projects on personal-scoped machines: scope routes between the lake and home storage (crossing is an explicit human decision), committed config points only at code and docs while `.env` alone holds data roots (role-named `HOME_<ROLE>_ROOT`, required-variable loud-failure pattern, no address defaults), plus the embedded-database-over-SMB, mirror-is-not-backup, name-not-IP, and least-privilege rules. Harvested from a gitignored machine-local storage doc; no hostname, share, pool, or drive path reaches git. `config/project.yaml` documents the new optional `project.scope` field and rosters this box; `.env.example` carries the variable names with placeholders. Reviewed by proposer + code-reviewer (`docs/reviews/20260830_home_storage_*.md`, GO-WITH-FIXES, all fixes applied).
- **Machine identity + lake conventions (2026-08-29 cycle)**: `config/project.yaml` gains a `machines:` roster keyed by hostname; `src/myproject/utils/machine.py` resolves the current box (first code to read project.yaml); `/session-start` Step 1.5 reports it. `lake-conventions` 1.0.0 harvested from `launch-control` and generalized; `scripts/lake_preflight.py` ships 6 checks with 24 tests, including the leg-threading check that names an unthreaded process before a run instead of after five days of production writes.
- **Figure Style doctrine: `designing-clear-data-displays` skill (1.1.0)**, copied whole from `stx-server` (built there 2026-08-27 from Tufte's books and course: proposal, adversarial challenge, 26 lead decisions, two gate reviews, an outside feedback round; 34 quotations verified by fetch). Five files: eight kernel rules with sources and tests, six generic before/after pairs, a five-pass review protocol, adoption steps. `CLAUDE.md` gains a Figure Style section beside Prose Style; `code-reviewer` gains one checklist line for figures; `SKILLS_FRAMEWORK.md` and `.claude/README.md` list it. `writing-simple-and-direct` 1.0.1 hands the chart-or-table question to the figure skill in one scope sentence.
- **Research tools on the two Level 0 reasoning agents**: `proposer` and `code-reviewer` `tools:` lines gain `WebSearch, WebFetch` so proposals and challenges can verify sources by fetch (a capability line, not project knowledge; first used for the Tufte ledger downstream). `.claude/README.md` states the capability-versus-knowledge distinction.

Ported from `stx-server` commit `62f20a1`, where feature-named suites had logged 27 false `MISSING_TEST` lines in one wave. Driven by `tests/unit/test_shift_left_hook.py` (9 tests over three behaviors, parametrized across the import forms and four near-miss names; the first written failing); `ENFORCEMENT.md` step 4 and its limitations updated.

- `tzdata; sys_platform == 'win32'` to the base dependencies in `pyproject.toml`. CPython's bundled `zoneinfo` has no backing data on Windows; installing `tzdata` makes named timezones work as expected. The `logger.py` fallback above guarantees graceful behavior even if the dep is missing.
