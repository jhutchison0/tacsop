# WHETSTONE Research Digest: Memory and Knowledge-Graph Systems (2024-2026)

**Commissioned**: 2026-08-14 by the session lead for CONOP WHETSTONE
**Author**: web research agent (systems lane)
**Status**: evidence record, verbatim as delivered; corrections land as dated addenda, never edits

## Findings

**1. Zep/Graphiti: bi-temporal typed edges with invalidate-not-delete.** Graphiti stores facts as typed edges (developer-prescribed via Pydantic or learned from data) carrying four timestamps (`valid_at`, `invalid_at`, `created_at`, `expired_at`), with every entity and edge tracing back to the source "episode" that produced it; contradiction triggers invalidation with history preserved, never deletion. Behavior changes next session because retrieval filters to currently-valid facts while point-in-time queries remain possible. The OSS engine runs fully local (Neo4j/FalkorDB plus Ollama for extraction); the hosted Zep platform does not. Sources: https://arxiv.org/abs/2501.13956, https://github.com/getzep/graphiti

**2. Letta (MemGPT): pinned memory blocks plus "sleep-time compute."** Behavior change comes from self-edited memory blocks (persona, human, project state) pinned into every session's context, and from a separate sleep-time agent that holds exclusive edit tools and rewrites the primary agent's blocks during idle periods, turning "raw context" into "learned context" (merging duplicates, resolving contradictions, pre-computing associations). The server is open source and self-hostable with local model backends; the memory model is blocks plus agentic search, not a graph. Reported cost: consolidation frequency directly trades tokens for memory quality and needs tuning. Sources: https://www.letta.com/blog/sleep-time-compute/, https://www.letta.com/blog/memory-blocks/

**3. Mem0: a write-time arbitration protocol (ADD / UPDATE / DELETE / NOOP).** For each candidate fact extracted from a session, Mem0 retrieves the most similar existing memories and an LLM decides to add, update, delete, or skip; that arbitration step, not retrieval, is its core idea, and its graph variant (Mem0g) adds entity-relation triplets with semantic matching. OSS Mem0 runs fully local with Ollama; the platform is cloud. What breaks: the update LLM silently rewrites memories (a documented drift vector), and its headline benchmark claims sparked a public dispute (finding 12). Sources: https://arxiv.org/abs/2504.19413, https://memo.d.foundation/breakdown/mem0

**4. Cognee: ontology-grounded ECL pipeline as a shared memory plane.** Cognee runs Extract-Cognify-Load: LLM extraction of entities/relations into a knowledge graph plus embeddings, optionally constrained by a user-supplied ontology so the graph vocabulary stays controlled rather than emergent. Cross-session behavior change comes from any agent (Claude, GPT, local Llama) querying the same self-hosted graph over MCP. Fully local stacks are supported; the cost is that every ingest is an LLM pipeline run with the same extraction-nondeterminism exposure as GraphRAG. Sources: https://github.com/topoteretes/cognee, https://www.cognee.ai/blog/deep-dives/grounding-ai-memory

**5. GraphRAG vs LazyGraphRAG: Microsoft abandoned precomputed summarization and matched quality at 0.1% of the cost.** Full GraphRAG precomputes an entity graph plus community summaries (indexing one dataset reportedly cost $33,000 in early 2024), and its incremental-update path shipped broken (graph output not actually updated, issue #1836); practitioners also report entity-resolution failure as the silent killer, since LLM extraction is non-deterministic and duplicate entities rot traversals. LazyGraphRAG keeps only lightweight graph construction at index time and defers all LLM summarization to query time under a "relevance test budget," achieving comparable quality at vector-RAG indexing cost and roughly 700x lower query cost than GraphRAG global search. This is the strongest external validation of tacsop's choice to traverse at read time instead of building an index. Sources: https://www.microsoft.com/en-us/research/blog/lazygraphrag-setting-a-new-standard-for-quality-and-cost/, https://github.com/microsoft/graphrag/issues/1836, https://www.sowmith.dev/blog/graphrag-entity-disambiguation

**6. LightRAG: dual-level retrieval keys.** LightRAG (EMNLP 2025, fully local-capable) indexes each graph element under two kinds of keys: low-level (specific entities) and high-level (broad themes), and answers queries by combining both, plus an incremental insert algorithm so new documents extend the graph without full re-indexing. The stealable idea is not the library but the convention: every knowledge artifact should be findable through both a fine-grained entry point (file, claim) and a coarse thematic one (hub, index). Source: https://arxiv.org/abs/2410.05779

**7. HippoRAG 2: multi-hop retrieval as spreading activation over links, and continual learning as append.** It runs Personalized PageRank over a graph of phrase and passage nodes seeded by query matches, so relevance flows along edges and documents reachable from multiple seeds win; new knowledge integrates by appending passages/triples with no retraining ("non-parametric continual learning"), gaining +7 F1 on associative tasks over the best embedding retriever. Runs fully local via vLLM-compatible servers. The zero-dependency analog is a traversal discipline, not code: expand one to two hops from each grep seed and rank by convergence. Sources: https://arxiv.org/abs/2502.14802, https://github.com/osu-nlp-group/hipporag

**8. A-MEM: Zettelkasten notes with a "memory evolution" step.** Each memory is an atomic note with LLM-generated keywords, tags, and a contextual description; on every add, the system links the new note to related ones and, critically, rewrites the contextual descriptions of the linked older notes so the network re-interprets itself as knowledge accrues. It is a library (local-capable), but the convention is fully stealable: writing a new doc should trigger updates to the docs it links to. Independent replication (MemoryBench, cited in the benchmark-theatre essay below) found A-MEM, Mem0, and MemoryOS do not consistently beat plain RAG baselines. Source: https://arxiv.org/abs/2502.12110

**9. Agent Workflow Memory: distill trajectories into reusable workflows.** AWM (Neubig group, 2024) mines past successful task trajectories for recurring sub-routines, abstracts away example-specific detail, and stores the resulting workflows in memory to guide future runs: 24.6% and 51.1% relative success-rate gains on Mind2Web/WebArena while reducing steps per solved task. This is the academic version of "promote repeated session patterns into skills," and it supplies the metric tacsop lacks: steps saved on later instances of the same task shape. Source: https://arxiv.org/abs/2409.07429

**10. Claude Code memory: a hard-capped always-loaded index with on-demand depth, and an explicit context-vs-enforcement split.** Auto memory loads only the first 200 lines or 25KB of `MEMORY.md` each session; overflow must move to topic files read on demand, the harness nags or errors when the index exceeds the cap, and files with frontmatter get a `modified` ISO-8601 timestamp so staleness is visible. The docs are blunt that CLAUDE.md and memory are "context, not enforced configuration": anything that must always happen belongs in hooks, and CLAUDE.md files over 200 lines measurably reduce adherence. Everything is local markdown, but the model calls are Anthropic cloud, so zero-egress it is not. Source: https://code.claude.com/docs/en/memory

**11. Obsidian-plus-agent setups: the vault as multi-agent shared memory, and a sharp critique.** The working pattern is a plain-markdown vault used as common memory by Claude Code, Codex, and local LLMs, governed by a checked-in "operating manual" note specifying where to file things, how to link, and when to split a note; Obsidian shipped official Agent Skills (Jan 2026) teaching agents its wikilink/frontmatter conventions. The critique worth hearing: wikilinks are not queryable relations, inconsistent naming breaks programmatic use, and unmanaged vaults hit a token-cost scale ceiling, so "memory" claims outrun reality without schema discipline and curation. Sources: https://www.xda-developers.com/my-obsidian-vault-is-shared-memory-for-claude-code-codex-and-local-llm/, https://limitededitionjonathan.substack.com/p/stop-calling-it-memory-the-problem

**12. What breaks everywhere: lifecycle neglect, poisoning, and benchmark theatre.** Surveys and practitioner postmortems converge on one diagnosis: systems nail write and read but neglect manage, so stores bloat, contradictions coexist, and rewrite-heavy consolidation drifts memories from their original meaning while the agent "keeps answering but answers slowly get worse." Memory poisoning is practical: MINJA achieved >95% injection success into agent memory through ordinary user queries, with the poison retrieved later as trusted context (git-reviewed memory writes are the natural defense tacsop already has). And published scores are unreliable: LoCoMo's ground truth is 6.4% wrong, standard LLM judges accepted 62.81% of deliberately wrong answers, Zep's 84% claim fell to 75.14% (their correction) or 58.44% (Mem0's replication), EverMemOS's 92.32% reproduced at 38.38%, and a plain filesystem with grep scored 74%, beating several dedicated memory products. Sources: https://arxiv.org/html/2603.07670v1, https://arxiv.org/abs/2601.05504, https://essays.bloo-mind.ai/posts/2026-05-20-mem-eval/, https://github.com/getzep/zep-papers/issues/5

## Steal list for tacsop

All five are conventions layered on the existing `.claude/skills/traversing-the-knowledge-base/SKILL.md` edge vocabulary (Follows, Documents, Implements, References, Completes, Requires, Cites); none require installing anything.

1. **Supersession headers with temporal validity (from Graphiti).** Add `**Supersedes**:` / `**Superseded-by**: <path> (YYYY-MM-DD)` to the typed-edge set, and never delete a doctrine claim: mark it invalid with date and pointer. One grep (`grep -rn "^\*\*Superseded-by\*\*"`) then yields the complete stale set, and lineage plus validity reconstructs "what was doctrine on date X" for any downstream-repo dispute.
2. **Write-time arbitration protocol (from Mem0).** Before adding a lesson or rule to any living doc, run the existing blast-radius grep for the nearest prior statement and record an explicit verdict in the session doc: ADD (new), UPDATE (refines), SUPERSEDE (replaces, add header), or NOOP (already covered). Contradiction accumulation is the top reported silent failure, and this is the cheapest known countermeasure.
3. **Scheduled consolidation session (from Letta sleep-time compute).** Define a session type whose only deliverable is memory hygiene: merge duplicate guidance, resolve contradictions, compress indexes, refresh CONTEXT.md's Reading Order and hub docs. Letta's evidence is that consolidation done outside live work sessions produces cleaner "learned context" than incremental in-session edits; the cadence is a tunable, visible cost.
4. **Hard caps on always-loaded surfaces (from Claude Code auto memory).** Adopt the 200-line/25KB rule editorially for CLAUDE.md, CONTEXT.md, and skill bodies across all 19 downstream repos: one line per entry in the always-loaded index, detail exiled to linked on-demand files. Claude Code enforces this mechanically because over-cap indexes measurably reduce adherence; tacsop can enforce it with a `/pcc` line-count check.
5. **Convergence ranking for traversal (from HippoRAG's Personalized PageRank).** Add one recipe to the traversal skill: when a question produces multiple grep seed hits, expand one to two hops of links/paths from each seed and read first the docs reached from two or more seeds. That is PageRank done with a pencil, and it is precisely what turns link-following from navigation into relevance ranking.

## Do not do

1. **Do not precompute corpus-wide graphs or summaries.** Full GraphRAG's economics ($33k-scale indexing), broken incremental updates, duplicate-entity rot, and non-deterministic LLM extraction all argue against it, and Microsoft's own LazyGraphRAG matched quality at 0.1% of the indexing cost by deferring synthesis to query time. The graphify rejection was correct; revisit only if a traversal demonstrably fails, per the skill's existing build trigger.
2. **Do not run append-only memory without a lifecycle owner.** Every failure survey names the same arc: write and read get built, manage gets skipped, and the store degrades through bloat, contradiction, and drift while outputs stay superficially fluent. Every memory surface needs a named curation mechanism (the arbitration protocol and consolidation session above) or it becomes noise.
3. **Do not choose or justify tooling by published memory benchmarks.** LoCoMo-based marketing collapsed under replication across vendors (84 to 58.44; 92.32 to 38.38; sub-10-point deltas are noise per the corrected analyses), while a filesystem plus grep scored 74%. Tacsop's own falsifiable five-session criterion (M1/M2/M3 in the traversal skill) is the right evaluation pattern; extend that, and ignore vendor leaderboards.
